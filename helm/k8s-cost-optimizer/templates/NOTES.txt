k8s-cost-optimizer {{ .Chart.AppVersion }} installed as {{ include "k8s-cost-optimizer.fullname" . }}.

MODE: {{ if .Values.analysis.apply }}*** APPLY — recommendations WILL be written to the cluster and pods WILL restart ***{{ else }}recommendation-only (no cluster mutation){{ end }}

Policy: CPU {{ .Values.policy.cpuStrategy }} x{{ .Values.policy.cpuSafetyFactor }}, memory {{ .Values.policy.memoryStrategy }} x{{ .Values.policy.memorySafetyFactor }}, over a {{ .Values.policy.observationWindow }} window.

1. Wait for the first analysis cycle (it runs immediately on startup):

   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "k8s-cost-optimizer.fullname" . }}

2. Port-forward the API:

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "k8s-cost-optimizer.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}

3. Look at what it found:

   curl -s localhost:{{ .Values.service.port }}/api/v1/summary | jq
   curl -s localhost:{{ .Values.service.port }}/api/v1/recommendations | jq '.recommendations[0]'

Every recommendation carries the evidence behind it: the observed statistics, the
strategy and margin used, and a reason. Recommendations the engine withheld appear
as BLOCKED or INSUFFICIENT_DATA with an explanation — read those first, since they
are where the engine is telling you something it is not confident about.
